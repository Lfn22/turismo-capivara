<action>
Decisão de design (CONTEXT.md): CONDUTOR pode logar independente do approvalStatus — acesso a funcionalidades restritas é controlado downstream pelos guards de rota, não no login.

Em `apps/api/src/modules/auth/auth.routes.ts`, localizar o bloco `reply.jwtSign(...)` no handler de login (linha ~78) e adicionar `approvalStatus` ao payload:

```typescript
// Localizar o bloco atual (aproximadamente):
const token = await reply.jwtSign(
  {
    sub: user.id,
    tenantId: user.tenantId,
    role: user.role,
    name: user.name,
  },
  { expiresIn: '1d' }
)

// Substituir por:
const token = await reply.jwtSign(
  {
    sub: user.id,
    tenantId: user.tenantId,
    role: user.role,
    name: user.name,
    approvalStatus: user.approvalStatus,
  },
  { expiresIn: '1d' }
)
```

Verificar que a query `prisma.user.findFirst` não usa `select` que excluiria `approvalStatus`. Se usar select explícito, adicionar `approvalStatus: true` ao objeto de select. A query atual retorna todos os campos do User — nenhuma alteração na query é necessária.
</action>

**Passo 1 — Adicionar função hashCpf em auth.routes.ts**

```typescript
import { createHmac } from 'crypto'

function hashCpf(cpf: string): string {
  const secret = process.env.CPF_SECRET

}
```
