- `preHandler: [authenticate]`
- Extract `userId = (request.user as any).sub`
- Fetch current email first (needed to hash it):
  ```typescript
  const existing = await prisma.user.findUnique({
    where: { id: userId },
    select: { email: true },
  })
  if (!existing) throw new AppError('Usuário não encontrado', 404)
  ```
- Compute anonymized email:
  ```typescript
  const salt = process.env.ANONYMIZATION_SALT ?? 'capivara-lgpd-salt-dev'

    .digest('hex')
  ```

  ```typescript

    where: { id: userId },

      email: anonymizedEmail,
    },
  })
  ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → GET /users/me/export | Authenticated user requests own PII; must be scoped to their own userId from JWT, never from query param |
| client → DELETE /users/me | Authenticated user triggers irreversible anonymization; no confirmation token needed per D-12 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Spoofing | GET /users/me/export | mitigate | userId sourced from `request.user.sub` (JWT claim), never from request body or query param — cannot be spoofed by caller |
| T-04-02 | Information Disclosure | GET /users/me/export | mitigate | `select` clause in Prisma query limits returned fields to id, name, email, role, createdAt — no password hash, no tenantId leaked |
| T-04-03 | Tampering | DELETE /users/me | mitigate | Prisma update scoped to `where: { id: userId }` from JWT; no caller-controlled WHERE clause |
| T-04-04 | Information Disclosure | ANONYMIZATION_SALT env var | mitigate | Salt sourced from `process.env.ANONYMIZATION_SALT`; dev fallback is fixed string — production MUST set this env var in Railway (noted in user_setup) |
| T-04-05 | Repudiation | DELETE /users/me | accept | Booking records preserved per D-12 — transactional history remains for disputes; user PII removed but business record intact |
| T-04-06 | Elevation of Privilege | Both endpoints | mitigate | `authenticate` middleware (plan 01-02) performs cross-tenant check — user from tenant A cannot call slug of tenant B |
</threat_model>
