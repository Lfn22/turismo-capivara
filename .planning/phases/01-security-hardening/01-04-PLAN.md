**GET /tenants/:slug/users/me/export handler:**
```typescript
const userId = request.user.sub

// Look up the user to get their email (JWT payload has no email field)
const user = await prisma.user.findUnique({
  where: { id: userId },
  select: { id: true, name: true, email: true, role: true, createdAt: true },
})
if (!user) throw new AppError('Usuário não encontrado', 404)

// Query bookings by customerEmail — Booking has no userId field
const bookings = await prisma.booking.findMany({
  where: { customerEmail: user.email },
  select: { id: true, slotId: true, status: true, createdAt: true },
})

return reply.status(200).send({ user, bookings })
```

**DELETE /users/me handler:**
```typescript
const userId = request.user.sub

// Fetch current email first (needed to hash it; JWT payload has no email)
const existing = await prisma.user.findUnique({
  where: { id: userId },
  select: { email: true },
})
if (!existing) throw new AppError('Usuário não encontrado', 404)

const salt = process.env.ANONYMIZATION_SALT ?? 'capivara-lgpd-salt-dev'
const anonymizedEmail = createHash('sha256')
  .update(existing.email + salt)
  .digest('hex')

// Update user PII only — booking rows are NOT touched (LGPD preserves transactional history)
await prisma.user.update({
  where: { id: userId },
  data: {
    name: 'Usuário Removido',
    email: anonymizedEmail,
  },
})

return reply.status(204).send()
```

**Error handling:** Both handlers throw AppError when user is not found. The global error
handler registered in plan 01-01 (app.setErrorHandler) catches AppError and returns the
correct statusCode + message. Do NOT wrap handlers in try/catch for AppError — just throw.

Do NOT inline `reply.status(401).send(...)` for auth — that is handled by authenticate middleware.
Do NOT use `reply.status(4xx)` inline for business logic errors — use `throw new AppError(message, statusCode)`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → GET /tenants/:slug/users/me/export | Authenticated user requests own PII; must be scoped to their own userId from JWT, never from query param |
| client → DELETE /tenants/:slug/users/me | Authenticated user triggers irreversible anonymization; no confirmation token needed per D-12 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Spoofing | GET /tenants/:slug/users/me/export | mitigate | userId sourced from `request.user.sub` (JWT claim), never from request body or query param — cannot be spoofed by caller |
| T-04-02 | Information Disclosure | GET /tenants/:slug/users/me/export | mitigate | `select` clause in Prisma query limits returned fields to id, name, email, role, createdAt — no password hash leaked |
| T-04-03 | Tampering | DELETE /tenants/:slug/users/me | mitigate | Prisma update scoped to `where: { id: userId }` from JWT; no caller-controlled WHERE clause |
| T-04-04 | Information Disclosure | ANONYMIZATION_SALT env var | mitigate | Salt sourced from `process.env.ANONYMIZATION_SALT`; dev fallback is fixed string — production MUST set this env var in Railway |
| T-04-05 | Repudiation | DELETE /tenants/:slug/users/me | accept | Booking records preserved per D-12 — transactional history remains for disputes; user PII removed but business record intact |
| T-04-06 | Elevation of Privilege | Both endpoints | mitigate | `authenticate` middleware (plan 01-02) performs cross-tenant check — user from tenant A cannot call slug of tenant B |
</threat_model>
