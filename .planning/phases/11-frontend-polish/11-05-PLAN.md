  <action>
Create three identical loading.tsx files. Each file contains only:

```typescript
export default function Loading() {
  return (
    <div style={{ backgroundColor: 'var(--stone-50)', minHeight: '100dvh' }} />
  )
}
```

Files to create:
1. `apps/web/app/destinos/[destination-slug]/loading.tsx`
2. `apps/web/app/[slug]/(public)/roteiros/[packageId]/loading.tsx`
3. `apps/web/app/[slug]/(public)/checkout/loading.tsx`

Why these three routes:
- `destinos/[destination-slug]` — fetches destination + guides data (SSR)
- `[slug]/(public)/roteiros/[packageId]` — fetches roteiro detail (SSR)
- `[slug]/(public)/checkout` — fetches booking state (SSR, most likely to flash on mobile)

Why `100dvh` not `100vh`: Mobile Safari treats 100vh as viewport with browser chrome; 100dvh is the dynamic viewport (without chrome) — prevents layout jump on iOS.

Do NOT create loading.tsx at:
- `apps/web/app/loading.tsx` (root) — affects homepage which has its own background management
- Routes with client-only rendering — loading.tsx only helps SSR routes

