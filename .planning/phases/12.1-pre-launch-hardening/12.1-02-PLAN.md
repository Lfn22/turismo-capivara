<objective>
Configurar connection pool do Prisma via parâmetros na DATABASE_URL do Railway para evitar esgotamento de conexões sob carga.

Purpose: PostgreSQL no plano gratuito do Railway limita conexões simultâneas. Sem `connection_limit`, múltiplas requisições paralelas podem abrir conexões indefinidamente e causar erro "too many connections".
Output: DATABASE_URL no Railway atualizada com `?connection_limit=10&pool_timeout=2`. Schema Prisma com `directUrl` separada para migrações (necessário quando DATABASE_URL tem pooler como PgBouncer ou proxy).
</objective>

  <action>
No bloco `datasource db` em `apps/api/prisma/schema.prisma`, adicionar campo `directUrl` apontando para `DIRECT_URL`:

Estado atual:
```prisma
datasource db {
  provider = "postgresql"
}
```

Estado final:
```prisma
datasource db {
  provider   = "postgresql"
  url        = env("DATABASE_URL")
  directUrl  = env("DIRECT_URL")
}
```

Motivo: quando DATABASE_URL usa connection pooler (PgBouncer / Prisma Accelerate / proxy), migrações devem usar conexão direta. DIRECT_URL é a mesma URL sem os query params de pool. No Railway sem pooler externo, DIRECT_URL = DATABASE_URL original (sem ?connection_limit). Isso evita falha em `prisma migrate deploy` em produção.

Nota: o campo `url` já deve ser env("DATABASE_URL") — se o bloco atual não tem `url = env("DATABASE_URL")`, adicioná-lo também.
