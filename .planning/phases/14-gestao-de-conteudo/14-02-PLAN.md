  <action>
Create or expand destinations.service.ts with these methods:

**1. createDestination(tenantId: string, userId: string, input: CreateDestinationInput)**
   - Generates slug from name using simple slugify: name.toLowerCase().replace(/\s+/g, '-').replace(/[^\w-]/g, '')
   - Ensures slug is unique within tenant (check for existing, append -2, -3 if duplicate)
   - Calls prisma.destination.create({
       data: {
         tenantId,
         slug,
         name: input.name,
         description: input.description,
         state: input.state,
         photos: input.photos || [],
         highlights: input.highlights || [],
         approvalStatus: 'PENDING', // Always PENDING on creation per D-06
         createdById: userId, // From JWT
       }
     })
   - Returns created destination object

**2. updateDestination(destinationId: string, userId: string, input: UpdateDestinationInput)**
   - Fetch destination from DB
   - Check ownership: if (destination.createdById !== userId) throw AppError(403, 'Unauthorized')
   - Check approval status: if (destination.approvalStatus === 'APPROVED') throw AppError(400, 'Cannot edit approved destination') — guides can only edit PENDING/REJECTED
   - Call prisma.destination.update({
       where: { id: destinationId },
       data: {
         ...(input.name && { name: input.name }),
         ...(input.description && { description: input.description }),
         ...(input.state && { state: input.state }),
         ...(input.photos && { photos: input.photos }),
         ...(input.highlights && { highlights: input.highlights }),
       }
     })
   - Returns updated destination

**3. deleteDestination(destinationId: string, userId: string)**
   - Fetch destination
   - Check ownership: if (destination.createdById !== userId) throw AppError(403, 'Unauthorized')
   - Call prisma.destination.delete({ where: { id: destinationId } })
   - Returns { success: true }

Use prisma.$transaction for multi-step operations if needed (e.g., slug uniqueness check + insert).

Error messages in Portuguese: "Não autorizado", "Destino não encontrado", "Não é possível editar destino aprovado".

**1. POST /tenants/:slug/destinations** — Create destination
```
{
  preHandler: [authenticate, authorize(['ADMIN', 'CONDUTOR'])],
  schema: { body: CreateDestinationInput }
}
handler: async (request, reply) => {
  const { slug } = request.params
  const input = request.body
  const userId = request.user.id // From JWT
  
  Validate input with CreateDestinationInput.parse(input)
  If validation fails, catch ZodError and return 400 with field errors (in Portuguese)
  
  Call service.createDestination(slug, userId, input)
  Return 201 + created destination object
}
```

**2. PATCH /tenants/:slug/destinations/:id** — Update destination
```
{
  preHandler: [authenticate, authorize(['ADMIN', 'CONDUTOR'])],
  schema: { body: UpdateDestinationInput }
}
handler: async (request, reply) => {
  const { id } = request.params
  const input = request.body
  const userId = request.user.id
  
  Validate input with UpdateDestinationInput.parse(input)
  Call service.updateDestination(id, userId, input)
  Return 200 + updated destination
  On ownership check failure: return 403 "Unauthorized"
  On approval status error: return 400 "Cannot edit approved destination"
}
```

**3. DELETE /tenants/:slug/destinations/:id** — Delete destination

  Call service.deleteDestination(id, userId)
  Return 204 No Content

}

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Request JWT → User identity | Destination.createdById set from request.user.id (must be present in JWT) |
| Input → Database | Zod validation on all destination fields before insert/update |
| Guide → Own destinations | ownership check: destination.createdById === request.user.id before PATCH/DELETE |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-05 | Tampering (T) | POST body — fake state enum | Mitigate | Zod enum validation enforces 27-value whitelist |
| T-14-06 | Tampering (T) | PATCH — user edits another's destination | Mitigate | Service.updateDestination checks `createdById === userId` before update |
| T-14-07 | Tampering (T) | DELETE — user deletes another's destination | Mitigate | Service.deleteDestination checks `createdById === userId` before delete |
| T-14-08 | Authorization (A) | Guide tries to set approvalStatus to APPROVED | Mitigate | Input schema does NOT include approvalStatus field; only set by server in createDestination |
| T-14-09 | Integrity (I) | Photo URL tampering | Accept | Photos are URLs; R2 generates immutable signed URLs (Wave 2), no embedded secrets |

**Disposition rationale:**
- T-14-05/06/07: Mitigate via Zod + ownership checks
- T-14-08: Mitigate via schema design — approvalStatus never in input
- T-14-09: Accept — R2 URLs are publicly intended

</threat_model>
