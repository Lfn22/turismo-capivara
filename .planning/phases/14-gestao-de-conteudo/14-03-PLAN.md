```typescript
import { S3Client } from '@aws-sdk/client-s3'

const {
  CLOUDFLARE_ACCOUNT_ID,
  CLOUDFLARE_API_TOKEN,
  R2_BUCKET_NAME,
} = process.env

if (!CLOUDFLARE_ACCOUNT_ID || !CLOUDFLARE_API_TOKEN || !R2_BUCKET_NAME) {
  throw new Error('Missing required R2 env vars: CLOUDFLARE_ACCOUNT_ID, CLOUDFLARE_API_TOKEN, R2_BUCKET_NAME')
}

const r2Client = new S3Client({
  region: 'auto',
  endpoint: `https://${CLOUDFLARE_ACCOUNT_ID}.r2.cloudflarestorage.com`,
  credentials: {
    accessKeyId: CLOUDFLARE_API_TOKEN.split(':')[0], // Token format: access_key:secret
    secretAccessKey: CLOUDFLARE_API_TOKEN.split(':')[1],
  },
})

export { r2Client }
export const R2_BUCKET = R2_BUCKET_NAME
export const R2_PUBLIC_URL = `https://${R2_BUCKET_NAME}.${CLOUDFLARE_ACCOUNT_ID}.r2.dev` // Public URL domain
```

Create uploads.service.ts with file handling methods:

**1. validatePhotoFile(file: File) → { valid: boolean; error?: string }**
   - Check MIME type: JPEG (image/jpeg), PNG (image/png), WebP (image/webp)
   - Check file size: ≤ 5MB (5242880 bytes)
   - If invalid: return { valid: false, error: "Formato inválido. Use JPEG, PNG ou WebP." } or size error
   - Return { valid: true }

**2. uploadPhotoToR2(file: Buffer, fileName: string, folder: 'destinations' | 'packages') → { url: string; key: string }**
   - Generate unique key: `${folder}/${Date.now()}_${sanitizeFileName(fileName)}`
   - Call r2Client.send(new PutObjectCommand({
       Bucket: R2_BUCKET,
       Key: key,
       Body: file,
       ContentType: file.mimetype,
     }))
   - Construct public URL: `${R2_PUBLIC_URL}/${key}`
   - Return { url, key } for storage in database

**3. deletePhotoFromR2(key: string) → void** (future cleanup)
   - Call r2Client.send(new DeleteObjectCommand({
       Bucket: R2_BUCKET,
       Key: key,
     }))

**4. sanitizeFileName(fileName: string) → string**
   - Remove special characters, replace spaces with underscores
   - Keep only alphanumeric, dash, underscore: `fileName.replace(/[^\w.-]/g, '_')`

Error messages in Portuguese. Handle network errors gracefully (throw AppError).

Dependencies needed: @aws-sdk/client-s3, @aws-sdk/lib-storage (optional, for large files)

Create uploads.routes.ts with file upload endpoint:

**POST /uploads/photos** — Upload single photo
```
{
  preHandler: [authenticate, authorize(['ADMIN', 'CONDUTOR', 'CLIENTE'])],
  schema: {
    querystring: { folder: z.enum(['destinations', 'packages']) }
  }
}
handler: async (request, reply) => {
  const { folder } = request.query
  const file = await request.file() // Fastify multipart
  
  if (!file) return reply.status(400).send({ error: 'Nenhum arquivo enviado' })
  
  const buffer = await file.toBuffer()
  const validation = service.validatePhotoFile(buffer, file.filename, file.mimetype)
  if (!validation.valid) return reply.status(400).send({ error: validation.error })
  
  try {
    const { url, key } = await service.uploadPhotoToR2(buffer, file.filename, folder)
    return reply.status(200).send({ url, key })
  } catch (err) {
    return reply.status(500).send({ error: 'Falha ao fazer upload. Tente novamente.' })
  }
}
```

Use @fastify/multipart for file handling. Return JSON response with { url, key } on success.

**Rate limiting:** Optional — consider adding to prevent abuse. Skip for MVP.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Request file → Server validation | File format and size validated before upload to R2 |
| R2 credentials → Client | Credentials never exposed; only public URLs returned to client |
| Public R2 URLs → Internet | Photos are intentionally public (marketplace display) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-10 | Tampering (T) | File upload — malicious file format | Mitigate | MIME type whitelist (JPEG, PNG, WebP) validated on server |
| T-14-11 | Tampering (T) | File upload — oversized file (DoS) | Mitigate | 5MB size limit enforced before upload |
| T-14-12 | Information Disclosure (I) | R2 credentials leaked | Mitigate | Credentials stored in env vars, never exposed in responses |
| T-14-13 | Elevation of Privilege (E) | Non-guide user uploads photos | Mitigate | Auth middleware checks role (CONDUTOR or ADMIN for guides) |
| T-14-14 | Denial of Service (D) | Rate limit on uploads | Mitigate | Optional rate limiting (defer to v2); no limit in MVP |

**Disposition rationale:**
- T-14-10/11/12: Mitigate via validation + secrets management
- T-14-13: Mitigate via auth (CONDUTOR/ADMIN only)
- T-14-14: Accept for MVP (rate limit optional)

</threat_model>
