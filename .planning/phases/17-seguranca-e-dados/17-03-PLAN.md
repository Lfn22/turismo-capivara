## Goal

Adicionar isolamento de tenant nos handlers confirm/cancel, garantir decremento atômico de slot no cancelamento, e bloquear booking de guia não-aprovado.

## Context

Três gaps de integridade nos handlers de booking:
1. SEC-03: handlers PATCH confirm/cancel não verificam se o booking pertence ao tenant do JWT — qualquer usuário autenticado com JWT válido pode manipular booking de outro tenant.
2. DATA-01: O cancelamento precisa decrementar `bookedCount` do slot atomicamente. O `pre_gathered_context` indica que pode já existir `$transaction` — verificar e garantir que o decremento está presente.
3. DATA-02: POST /bookings não verifica se o guia (tenant) foi aprovado pela plataforma antes de criar a reserva.

Decisões: D-07 (403 check), D-10 (atomic decrement), D-11/D-12 (approval guard).

**Nota:** Este plano toca o mesmo arquivo que 17-02 (bookings.routes.ts). Executar APÓS 17-02 para evitar conflito de merge. Na prática, wave 2 pode ter ambos em paralelo se forem arquivos distintos — como ambos tocam bookings.routes.ts, o executor deve aplicar 17-02 primeiro, depois 17-03, ou trabalhar em branches separadas e mergear. Recomendado: executar 17-02 e 17-03 sequencialmente nesta ordem.

  <name>Task 2: Garantir decremento atômico de bookedCount no cancelamento</name>

  <read_first>
    - apps/api/src/modules/bookings/bookings.routes.ts (handler PATCH cancel — seção do $transaction)
  </read_first>

  <action>
Localizar o handler `PATCH /bookings/:id/cancel` (ou equivalente de cancelamento com auth).

Verificar se o `$transaction` já inclui o decremento de `bookedCount`. Dois casos possíveis:

**Caso A — $transaction existe mas não decrementa slot:**
Adicionar dentro do array de operações do `$transaction`:
```typescript
prisma.slot.update({
  where: { id: booking.slotId },
  data: { bookedCount: { decrement: 1 } }
})
```

**Caso B — $transaction já inclui decremento:**
Verificar que o update do slot está no mesmo array de `$transaction` que o update do booking (não em chamadas separadas fora da transação). Se estiver correto, nenhuma alteração necessária — documentar no SUMMARY.

**Caso C — Sem $transaction:**
Criar `prisma.$transaction([...])` envolvendo:
```typescript
prisma.booking.update({ where: { id }, data: { status: 'CANCELLED' } }),
prisma.slot.update({ where: { id: booking.slotId }, data: { bookedCount: { decrement: 1 } } })
```

Não decrementar se o booking já estava cancelado — verificar `if (booking.status === 'CANCELLED') throw new AppError('BOOKING_ALREADY_CANCELLED', 400)` antes da $transaction.
