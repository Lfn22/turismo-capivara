## Goal

Adicionar `cancelToken` ao modelo Booking e criar modelo `ProcessedWebhookEvent` para deduplicação idempotente de webhooks.

## Context

Atualmente o cancel-self deriva o booking via sufixo do `id` (UUID parcial), o que expõe o ID real e permite enumeração. A solução é um token opaco gerado com `crypto.randomBytes(32)`. Paralelamente, o webhook handler não tem deduplicação persistida — o modelo `ProcessedWebhookEvent` resolve isso.

Decisões aplicadas: D-03, D-04, D-05, D-08.
