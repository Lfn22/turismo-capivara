## Goal

Adicionar deduplicação idempotente de webhooks via ProcessedWebhookEvent e validação de data futura em slots (backend Zod + frontend fail-fast).

## Context

Dois problemas independentes resolvidos neste plano:

1. **SEC-04:** O handler de webhook do Mercado Pago não tem deduplicação — se o MP reenviar o mesmo evento, o booking será processado duas vezes. O modelo `ProcessedWebhookEvent` (criado no plano 17-01) é a solução: verificar se o `paymentId` já foi processado, registrá-lo após processamento.

2. **DATA-04:** Slots podem ser criados com datas no passado. Zod `.refine()` no backend retorna 400 `SLOT_DATE_PAST`. Frontend valida antes de chamar API (fail-fast, D-14).

Decisões: D-08, D-09, D-13, D-14, D-15.

  <action>
No handler do webhook do Mercado Pago em `webhooks.routes.ts`:

1. **Após** a validação de assinatura HMAC (que já existe), extrair o `paymentId` do payload. Tipicamente:
```typescript
const paymentId = body?.data?.id?.toString()
if (!paymentId) return reply.status(200).send({ ok: true }) // ignorar pings sem ID
```

2. **Verificar deduplicação** antes de qualquer lógica de negócio:
```typescript
const alreadyProcessed = await prisma.processedWebhookEvent.findUnique({
  where: { id: paymentId }
})
if (alreadyProcessed) {
  return reply.status(200).send({ ok: true, deduplicated: true })
}
```

3. **Após processar** o evento com sucesso (update do booking, etc.), registrar no final do bloco de processamento (dentro de `$transaction` se possível, ou logo após):
```typescript
await prisma.processedWebhookEvent.create({
  data: { id: paymentId }
})
```

Idealmente, o `create` do `ProcessedWebhookEvent` deve estar no mesmo `$transaction` que o update do booking para garantia atômica. Se o handler já usa `$transaction`, adicionar o create ao array. Se não usa, envolver em `$transaction`.

4. **Janela de deduplicação:** O cleanup de registros mais antigos que 7 dias está deferido para a fase OPS (D-09) — não implementar cron aqui.

Não alterar a validação HMAC existente nem o `config: { rawBody: true, rateLimit: false }`.

**Backend — slots.routes.ts:**

Localizar o schema Zod do body do `POST /slots` (ou equivalente de criação de slot). Adicionar `.refine()` no campo `startsAt`:

```typescript
const createSlotSchema = z.object({
  startsAt: z
    .string()
    .datetime()
    .refine((val) => new Date(val) > new Date(), {
      message: 'Data do slot não pode ser no passado',
    }),
  // ... demais campos
})
```

Se `startsAt` for `z.date()` em vez de `z.string().datetime()`, usar:
```typescript
startsAt: z.date().refine((val) => val > new Date(), {
  message: 'Data do slot não pode ser no passado',
})
```

O handler deve retornar 400 com código `SLOT_DATE_PAST` quando a validação falha. Se o handler usa o erro padrão do Zod (que já retorna 400), adicionar o código customizado via `AppError` ou garantir que o código `SLOT_DATE_PAST` apareça na resposta. Exemplo com transformação do erro Zod:

```typescript
// Se o projeto tem middleware de tratamento de erros Zod:
// O message 'Data do slot não pode ser no passado' deve ser mapeado para { code: 'SLOT_DATE_PAST' }
// Se não, adicionar verificação manual antes do $transaction:
if (new Date(body.startsAt) <= new Date()) {
  throw new AppError('SLOT_DATE_PAST', 400, 'Data do slot não pode ser no passado')
}
```

Usar a abordagem consistente com o resto do projeto (verificar como outros handlers retornam erros de validação).

**Frontend — page.tsx:**

No formulário de criação de slot, adicionar validação client-side no submit ou no campo de data:

```typescript
// No handler de submit ou na validação do form (react-hook-form, zod, ou manual):
if (new Date(formData.startsAt) <= new Date()) {
  setError('startsAt', { message: 'Data do slot não pode ser no passado' })
  return // não chamar API
}
```

Se o projeto usa react-hook-form + zod no frontend, adicionar o mesmo `.refine()` ao schema do frontend. Se usa validação manual, adicionar o check antes do `fetch`/`axios`.

A mensagem exibida ao usuário pode ser em PT-BR: "Data do slot não pode ser no passado".
