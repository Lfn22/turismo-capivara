## Goal

Corrigir rate limit de cancel-self para usar IP (não email) com max 3, e substituir lookup por cancelToken opaco.

## Context

Dois problemas de segurança no cancel-self atual:
1. Rate limit usa `keyGenerator: req => 'lookup:email:${email}'` — keyed por email, facilmente contornável com IPs diferentes. Deve ser `req.ip`, max 3, '15 minutes' (D-01).
2. Lookup faz `findFirst({ where: { id: { endsWith: code.toLowerCase() } } })` — deriva booking pelo ID, expondo a estrutura. Deve ser `findFirst({ where: { cancelToken: token, tenantId: tenant.id } })` (D-03, D-04).

O POST /bookings (criação) também precisa gerar o cancelToken no $transaction.

  <action>
Em `bookings.routes.ts`, localizar a rota de cancel-self (GET /bookings/cancel-self ou similar).

**Alterar config de rate limit:**
De:
```typescript
config: { rateLimit: { max: 5, timeWindow: '15 minutes', keyGenerator: (req) => `lookup:email:${email}` } }
```
Para:
```typescript
config: { rateLimit: { max: 3, timeWindow: '15 minutes', keyGenerator: (req) => req.ip } }
```
Nota: `keyGenerator` recebe `(req)` — usar `req.ip` diretamente. Remover qualquer referência a email na keyGenerator.

**Alterar lookup do booking:**
De:
```typescript
prisma.booking.findFirst({ where: { id: { endsWith: code.toLowerCase() }, tenantId: tenant.id } })
```
Para:
```typescript
prisma.booking.findFirst({ where: { cancelToken: token, tenantId: tenant.id } })
```
O parâmetro de query string que o usuário fornece passa a ser `token` (não `code`). Ajustar parsing do query param correspondentemente. Se o param se chamava `code`, renomear para `token` na query string e na variável local.

**Adicionar import de crypto** no topo do arquivo se ainda não existir:
```typescript
import crypto from 'crypto'
```
