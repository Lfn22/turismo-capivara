     ]
   }

Add a new public route handler (no auth middleware) at bookings.routes.ts:

```
GET /tenants/:slug/bookings/:id?email=xxx
```

Handler logic:
1. Parse `params.id` (bookingId) using Zod string validation
2. Extract query param `email` from request — required
3. Fetch booking where id matches and tenantId matches slug
4. If booking NOT found OR `booking.customerEmail !== queryParam.email` → return 404 (no expose of existence)
5. If found and email matches, return booking details:
   ```json
   {
     "id": "booking-uuid",
     "status": "PENDING|CONFIRMED|CANCELLED",
     "customerName": "João Silva",
     "customerEmail": "joao@example.com",
     "pax": 2,
     "createdAt": "2026-05-13T10:30:00Z",
     "slot": {
       "startsAt": "2026-05-20T09:00:00Z"
     },
     "package": {
       "id": "pkg-uuid",
       "name": "Trilha da Serra",
       "price": "150.00"
     },
     "guide": {
       "id": "guide-uuid",
       "name": "Maria Condutora"
     }
   }
   ```
6. **NEVER return customerCpf, customerPhone, or paymentUrl in response** (sensitive data)
7. Validation error (missing email param) → return 400 with message "EMAIL_PARAM_REQUIRED"

Use Zod to validate params and query. No authentication required (public endpoint with email guard).

Per D-05, D-08.

| Boundary | Description |
|----------|-------------|
| Public GET /packages/:id/slots | Untrusted client (tourist) reads slot data |
| Public GET /bookings/:id?email=xxx | Untrusted client supplies email parameter; must validate against booking record |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Tampering | GET /bookings/:id email param | Mitigate | Email query param must match booking.customerEmail exactly; return 404 on mismatch (do not leak booking existence) |
| T-06-02 | Information Disclosure | GET /bookings/:id response | Mitigate | Strip customerCpf, customerPhone, paymentUrl from response; return only non-sensitive fields |
| T-06-03 | Information Disclosure | GET /packages/:id/slots | Accept | Slots are public marketing data; no PII, no pricing per person, no capacity breach risk |
</threat_model>
