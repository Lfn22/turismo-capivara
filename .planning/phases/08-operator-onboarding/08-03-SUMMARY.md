## What Was Built

### Middleware Protection (apps/web/middleware.ts)
- Extended `config.matcher` with `/super-admin/:path*`
- Unauthenticated `/super-admin/*` requests redirect to `/` (no slug-based login exists)
- Authenticated non-SUPER_ADMIN requests redirect to `/login?error=forbidden`
- Guard added so `/admin` check in middleware does not fire for `/super-admin` paths

### Route Handlers (3 files)
All use `getToken({ req, secret: NEXTAUTH_SECRET })` to forward JWT as Bearer header to Fastify:
- `GET /api/super-admin/tenants/pending` → `GET /tenants/admin/pending`
- `PATCH /api/super-admin/tenants/[id]/approve` → `PATCH /tenants/:id/approve`
- `PATCH /api/super-admin/tenants/[id]/reject` → `PATCH /tenants/:id/reject`

Next.js 16 async params pattern used: `params: Promise<{ id: string }>` with `await params`.

### /onboarding (apps/web/app/onboarding/page.tsx)
- Client Component with 4 fields: name, slug, email, password
- `slugify()` inline helper auto-populates slug from operator name
- Manual slug edit disables auto-generation via `slugAutoGenerated` ref
- 500ms debounced `GET /tenants/check-slug?slug=xxx` call with 5 states: idle | checking | available | unavailable | invalid-format
- Inline status indicator with aria-live="polite"
- Successful submit POSTs to `/tenants/signup` and redirects to `/onboarding/aguardando`
- Mobile-first: `100dvh`, `clamp()` padding, full-width form

### /onboarding/aguardando (apps/web/app/onboarding/aguardando/page.tsx)
- Server Component (no "use client")
- Static 3-item checklist: ✓ Cadastro enviado, ○ Aguardando aprovação, ○ Acesso liberado
- "Voltar para o início" link

### /super-admin/operadoras (apps/web/app/super-admin/operadoras/page.tsx)
- Client Component with shimmer skeleton loading (3 rows, linear-gradient animation)
- Table columns: Nome, Slug, Email, Cadastro, Status, Ações
- Status badges: PENDING (amber), APPROVED (green), REJECTED (red)
- Approve: optimistic update sets row to APPROVED; rolls back on API error
- Reject: opens Modal with required textarea; PATCH sends `{ reason }` to API
- Empty reason submit shows inline error "Informe o motivo da rejeição."
- Mobile: `overflowX: auto` wrapper + `flexWrap: wrap` on action buttons
- Uses existing `Modal` component (named export, `open` prop)

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Modal `open` prop vs `isOpen`**
- **Found during:** Task 3
- **Issue:** Plan specified `isOpen={!!rejectTarget}` but existing `Modal` component uses `open` prop
- **Fix:** Used `open={!!rejectTarget}` to match actual component API
- **Files modified:** apps/web/app/super-admin/operadoras/page.tsx
- **Commit:** 10a784c

**2. [Rule 1 - Bug] Next.js 16 async params**
- **Found during:** Task 1
- **Issue:** Plan showed `{ params }: { params: { id: string } }` (sync params) but project uses Next.js 16 where params are async Promises
- **Fix:** Used `params: Promise<{ id: string }>` with `await params` — consistent with existing pages (e.g., destinos/[destination-slug])
- **Files modified:** approve/route.ts, reject/route.ts
- **Commit:** 635246e

**3. [Rule 1 - Bug] Middleware /admin check fires for /super-admin**
- **Found during:** Task 1
- **Issue:** Existing `/admin` role check `if (pathname.includes("/admin"))` would match `/super-admin/*` paths and redirect SUPER_ADMIN users (who have role SUPER_ADMIN, not ADMIN) to `/{slug}/login`
- **Fix:** Added `!pathname.startsWith('/super-admin')` guard to the ADMIN check
- **Files modified:** apps/web/middleware.ts
- **Commit:** 635246e
