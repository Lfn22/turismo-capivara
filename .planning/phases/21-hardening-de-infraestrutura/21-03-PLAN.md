**3. Health check — substituir handler existente:**
Localizar a rota GET /health existente. Substituir o handler pelo seguinte:

```typescript
app.get('/health', async (request, reply) => {
  try {
    await prisma.$queryRaw`SELECT 1`;
    return reply.status(200).send({ db: 'ok' });
  } catch (error) {
    app.log.error({ err: error }, 'Health check DB probe failed');
    return reply.status(503).send({ db: 'error' });
  }
});
```

- O objeto de resposta 503 é `{ db: 'error' }` — não incluir `error.message` ou qualquer detalhe da exception na resposta HTTP.
- O detalhe completo do erro vai apenas para `app.log.error(...)` (server-side).
- Se `prisma` já está importado/acessível no escopo, usar o mesmo nome. Não criar nova instância.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-03-01 | Information Disclosure | GET /health response on 503 | mitigate | Resposta 503 retorna apenas `{ db: 'error' }` — detalhe da exception vai apenas para `app.log.error()`; nunca incluir `error.message` no body |
| T-21-03-02 | Spoofing | X-Request-Id header | mitigate | `genReqId` gera UUID v4 server-side via `crypto.randomUUID()`; request.id é imutável após geração — cliente não pode influenciar o valor |
| T-21-03-03 | Denial of Service | connectionTimeout ausente | mitigate | `connectionTimeout: 10000` limita conexões penduradas a 10s |
| T-21-03-04 | Information Disclosure | JWT expiresIn '7d' | accept | Tokens vivem 7 dias (up de 1d); risco aceitável — refresh flow ou revogação explícita não está no escopo desta fase |
</threat_model>
